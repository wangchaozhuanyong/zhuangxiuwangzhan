# Codex 任务 C8：路由登记与文档同步

> 投放方式：整篇粘给 Codex。

## 1. 项目背景（自包含）

仓库 `flashcast-website` 有两套强制登记机制，新增路由必须同步，否则 CI 里的检查会失败：

### 1.1 交互合规登记

`docs/interaction-route-compliance.json`，结构：

```json
{
  "version": 2,
  "standards": "docs/rules/loading-refresh-navigation.md",
  "routes": [
    {
      "path": "/admin",
      "surface": "admin",
      "source": "src/routes/adminRoutes.tsx",
      "loading": "...",
      "refresh": "...",
      "navigation": "...",
      "editing": "...",
      "acceptance": "PASS_LOCAL_SIMULATED",
      "samplePath": "/admin",
      "component": "AdminLogin + AdminLayout"
    }
  ],
  "validation": { ... }
}
```

检查脚本：`npm run verify:interaction-standards`

### 1.2 架构检查

`npm run arch:check` → `scripts/arch-check.mjs`，会校验：
- 模块边界（16 个一级模块）
- 层级职责（routes / controller / service / repository 不许混写）
- 跨模块 import

### 1.3 相关规则文档

- `docs/ARCHITECTURE.md`（固定架构边界）
- `docs/rules/loading-refresh-navigation.md`（加载/刷新/导航/编辑保护标准）
- `AGENTS.md`（总规则入口）

## 4. 允许修改 / 禁止修改

**允许**：
- `docs/interaction-route-compliance.json`（追加路由条目）
- `docs/ARCHITECTURE.md`（如需补充新路由层级说明）
- `docs/rules/loading-refresh-navigation.md`（如需补充新路由类型的标准）
- `AGENTS.md`（**仅在**需要补一行路由说明时，且不得改动 16 个模块清单）

**禁止**：
- 不要改 `AGENTS.md` 的 16 个一级模块列表
- 不要为了让检查通过而修改 `scripts/arch-check.mjs` 的判定规则
- 不要删除或覆盖已有路由条目
- 不要把 `acceptance` 字段填成假值（如填 `PASS` 但没实测）

## 5. 硬性要求

1. **每条新路由都要有独立条目**，字段不能空：
   - `path`：实际路径模式，如 `/:[lang]/locations/:area/:service`
   - `surface`：`public`
   - `source`：`src/routes/publicRoutes.tsx`
   - `loading`：实际加载行为（lazy + 是否有 loading state）
   - `refresh`：刷新行为（数据重取策略）
   - `navigation`：导航行为（是否保留公共 chrome、ScrollToTop）
   - `editing`：如有表单/编辑，写清楚；无则写 `n/a` 并说明
   - `acceptance`：**必须基于真实验收**，格式对齐现有条目（如 `PASS_LOCAL_SIMULATED`）
   - `samplePath`：一个真实可访问的示例路径
   - `component`：组件名

2. **`acceptance` 必须能追溯**。如果是本地模拟验收，就写 `PASS_LOCAL_SIMULATED`；如果只在 dev 环境看过，**不要写 PASS**，写实际状态并在报告里说明差距。

3. **`ARCHITECTURE.md` 补充内容**：在路由层级说明处加一句交叉页的定位，例如「`/:lang/locations/:area/:service` 为 service × service_area 交叉展示层，不新增业务模块」。不要写成长篇。

4. **检查必须真跑**：
```bash
npm run verify:interaction-standards
npm run arch:check
```
不能只「应该能过」。

5. **不要顺带重构**。这个任务的 PR 只包含登记与文档，不夹带代码改动。发现其他问题写进报告，不要顺手改。

## 6. 验收标准

- [ ] `docs/interaction-route-compliance.json` 中每条新路由字段完整、无空值
- [ ] JSON 语法合法（能被 `JSON.parse` 解析）
- [ ] `npm run verify:interaction-standards` 通过
- [ ] `npm run arch:check` 通过
- [ ] `docs/ARCHITECTURE.md` 有交叉页定位说明（一句话级别）
- [ ] `AGENTS.md` 的 16 个模块清单未被改动（用 `git diff` 证明）
- [ ] 报告里列出每条路由的 `acceptance` 依据

## 9. 边界处理

| 情况 | 处理 |
|---|---|
| `verify:interaction-standards` 因其他历史路由报错 | 报告是哪条历史条目导致，**不要顺手修无关条目**，标注为独立问题 |
| `arch:check` 报跨模块依赖 | 这是 C1 的实现问题，退回 C1 修，本任务不要用改规则的方式绕过 |
| 不确定 `acceptance` 该填什么 | 填最保守的真实状态，并在报告里写「建议补哪些验收后再升级状态」 |
