## 1. 项目背景（自包含，不需要本会话上下文）

本项目是马来西亚装修公司 FLASH CAST 的网站仓库。仓库里同时跑两个资产：

| 资产 | 域名 | 实现方式 |
|---|---|---|

| 电子锁展示站 | `locks.flashcast.com.my` | 同一个 Cloudflare Pages 项目 + 自定义域名，由 `functions/anzheShowroom.ts` 转发静态文件 |

电子锁展示站现状（已上线，勿推翻设计）：

- 静态源文件：`public/anzhe-showroom/`
- 三语首页：`public/anzhe-showroom/{zh,en,ms}/index.html`（各 ~90KB，手写 HTML）
- 共享脚本：`catalog.js`（17 款型号数据，挂在 `globalThis.lockCatalog`）、`features.js`、`panels.js`、`strings.js`、`directory.js`、`studio.js`、`contact.js`、`contact-float.js`、`showroom-boot.js`

  `V37J-P16 / 2360`、`P59J PRO / 2960`、`K16J-K19 / 2270`、`Q58J-K19 / 2270`、`K19J / 2120`、`Q8J / 2060`、`R10J-22 / 1970`、`K26J Pro / 1790`、`T06J / 1730`、`A88-Face ID / 1610`、`GP08 / 1250`、`F8 / 1220`、`G53 PRO / 1040`、`G86F-Pro / 712`、`G5 / 1070`、`G13 / 635.20`、`D10B / 1220`

**当前致命问题**：所有 17 款型号都在同一个页面里，没有任何独立 URL。搜索 `ANZHE V37J-P16 price`、`K26J Pro review` 这类型号词时，站点无法作为独立结果出现；`Product` schema 也不存在，Google 无法生成价格富媒体结果。

## 4.1 路由登记口径（必读，防止再次误判）

**子域静态路由不登记进 `docs/interaction-route-compliance.json`。**

证据链：

| 位置 | 事实 |
|---|---|
| `scripts/lib/interaction-route-inventory.mjs:29` | 只遍历 `src/routes/publicRoutes.tsx` 与 `src/routes/adminRoutes.tsx`，从 `Route` JSX 派生清单 |
| `scripts/verify-interaction-standards.mjs:24` | 登记表里任何不在扫描结果中的 key 都会被判 `Stale route registration` |
| `docs/rules/loading-refresh-navigation.md:78-82` | 已有「ANZHE 电子锁独立子域名」专节，子域规则登记在这里，不是 CI 校验表 |

结论：该表语义是 **React 路由的加载/刷新/导航行为**，子域是「静态 HTML + `functions/anzheShowroom.ts` 转发」，两者不同层。把它塞进该表会让 `verify:interaction-standards` 直接失败，且修 scanner 属于扩大本次范围。

因此本任务的登记口径是：

1. **不新增任何 `docs/interaction-route-compliance.json` 条目**
2. 在 `docs/rules/loading-refresh-navigation.md` 的子域小节补一段：型号页路径格式、非法 slug 返回 404、页面不依赖 JS 也能读到标题/价格/规格
3. 交互验收走 Playwright：新增 `e2e/anzhe-showroom-lock-pages.spec.ts`，复用 `e2e/anzhe-showroom-loading.spec.ts` 的 `serveShowroom()` 本地代理方式（`public/anzhe-showroom` 直接映射），断言：
   - `/zh/lock/v37j-p16/` 首屏有一个 `<h1>`，含型号名
   - 关闭 JS 后仍能读到价格文本
   - `/zh/lock/not-a-model/` 返回 404
4. `npm run verify:interaction-standards` 必须在**不新增登记条目**的前提下通过（它只校验 `src/**` 与两个 routes 文件，本次不碰这两处）

## 5. 硬性实现要求

### 5.1 中间件正则（最容易漏的一步）

`functions/anzheShowroom.ts` 现在只放行首页三语：

```ts
const pagePath = /^\/(zh|en|ms)(?:\/(index\.html)?)?$/;
```

**必须**扩展为同时接受型号页，且不得放宽为通配（防止任意路径返回 200 造成无限薄页）：

```ts
const LOCK_SLUGS = "v37j-p16|p59j-pro|k16j-k19|q58j-k19|k19j|q8j|r10j-22|k26j-pro|t06j|a88-face-id|gp08|f8|g53-pro|g86f-pro|g5|g13|d10b";
const pagePath = new RegExp(`^/(zh|en|ms)(?:/(?:index\\.html)?|/lock/(?:${LOCK_SLUGS})/?)$`);
```

要点：

- 非法 slug 必须 **404**，不得 fallback 到首页
- `serveDocument` 里 `origin.pathname` 的拼装要跟着支持子路径（现在是 `/zh/` 硬编码），改完后缓存 key 必须包含完整路径，不能所有型号共用一个缓存 key
- 带 `index.html` 的请求仍按现有逻辑 301 到干净 URL

### 5.2 页面生成而不是手写 51 份

新增 `scripts/generate-anzhe-lock-pages.mjs`：

- 读 `public/anzhe-showroom/catalog.js` 里的型号数组（可用 `esbuild` 或 `vm` 求值取 `globalThis.lockCatalog`；不要正则抠数字）
- 叠加 `docs/seo/anzhe-lock-page-copy.json`（本次同时交付的三语文案文件）里的标题/描述/FAQ
- 输出 51 个 `index.html`，每个 ≥ 6,000 字符可见文本
- 幂等：重复运行结果一致；`--check` 模式用于 CI 校验是否过期

### 5.3 HTML 结构

- 复用现有 CSS 与 `strings.js` 的语言机制，不新引入框架
- 不得使用内联 `<script>`：`anzheShowroom.ts` 的 CSP 是 `script-src 'self'`，内联脚本会被浏览器拦掉
- 图片只用现有 `assets/` 下文件，`width` / `height` / `loading` / `decoding` 必须齐全
- 全部页面必须能在关闭 JS 的情况下读到型号、价格、规格（爬虫与 AI 抓取依赖这个）

### 5.4 sitemap

`public/anzhe-showroom/sitemap.xml` 扩到 54 条（3 首页 + 51 型号页），每条带 `xhtml:link` 三语互指。**使用标准 `sitemap` 命名空间，不要加主站的 `image:` 扩展。**

同时：`functions/anzheShowroom.ts` 的 `staticFiles` 正则要放行 `llms.txt`（L2 用）与 IndexNow 验证文件 `89a0d82405fcdd4e83a37a2c1608813e.txt`（已放在 `public/anzhe-showroom/` 根目录）。两者都必须能通过 `https://locks.flashcast.com.my/<文件名>` 直接访问，否则 IndexNow 推送与 AI 抓取都会失败。

### 5.5 中文与马来语

- 中文文案由本次交付文件提供
- 马来语文案由本次交付文件提供，**必须是母语级**；若无法确认质量，ms 页加 `<meta name="robots" content="noindex">`，等译者校完再放开
- 三语 canonical 互不指向对方，各自 self-canonical，`hreflang` 互相声明
