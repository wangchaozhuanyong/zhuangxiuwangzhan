## 5. 硬性实现要求

### 5.1 性能门槛

在移动端 390×844、Slow 4G 节流下实测：

| 指标 | 门槛 |
|---|---|
| LCP | ≤ 2.5s |
| CLS | ≤ 0.1 |
| INP | ≤ 200ms |
| 首屏图片请求 | ≤ 2 个 |
| 首屏 HTML | ≤ 40KB（型号页） |

达不到就说明还有图片没压或没设优先级，不要用「网络环境差」解释。

### 5.2 图片

- 首屏 LCP 图：`fetchpriority="high"`、`loading="eager"`、显式 `width` / `height`
- 非首屏图：`loading="lazy"`、`decoding="async"`
- 所有图必须有 `sizes`，按实际布局断点写，不许留空或写 `100vw`
- 卡片缩略图 `width` / `height` 必须与实际渲染尺寸成比例，防止 CLS
- 已有 `scripts/convert-images-to-webp.mjs`，需要重新压图就用它，不要手写压缩脚本

### 5.3 可访问性

- 每页有且仅有一个 `<h1>`
- 所有 `<a>` 有可读文本，不用「点击这里」
- 型号卡的链接必须有 `aria-label`，包含型号名与含安装价
- 图片 `alt` 描述实际内容，不堆关键词
- 键盘 Tab 顺序覆盖：语言切换 → 导航 → 型号列表 → CTA
- 颜色对比度：正文 ≥ 4.5:1，大字号 ≥ 3:1（用 axe 或 Lighthouse 验证，贴结果）

### 5.4 结构完整性矩阵

生成一份逐条实测表（curl 原文）：

| 测试 | 预期 |
|---|---|
| 每个合法 URL 带尾斜杠 | 200 |
| 每个合法 URL 无尾斜杠 | 301 → 带斜杠 |
| 每个合法 URL + `/index.html` | 301 → 带斜杠 |
| 非法型号 slug | 404 |
| 非法品类 slug | 404 |
| 非法语言前缀（`/fr/lock/...`） | 404 |
| 根路径 `/` | 302 → 语言首页 |
| 每个页面的 canonical | 自指 |
| 每个页面的 hreflang | 三语齐全 + x-default |

### 5.5 缓存

- HTML：`Cache-Control` 与现有 `applyPublicHtmlEdgeCacheHeaders` 一致，不许改成长期缓存
- 带指纹的静态资源：`immutable`
- 无指纹的静态资源：`no-cache`

## 9. 边界与失败处理

| 情况 | 处理 |
|---|---|
| 压图后视觉明显变差 | 回退该图，改用更小尺寸而非更低质量 |
| LCP 达标但 CLS 变差 | 优先修 CLS，宽高比必须写死 |
| 某个 a11y 项改不动（如第三方资源） | 记入未完成项，说明原因，不要假装通过 |
| 改缓存头导致页面不更新 | 立即回滚缓存改动，这是线上事故级别 |
| 与 L6 分支冲突 | 说明冲突文件，等 main 更新后 rebase |
