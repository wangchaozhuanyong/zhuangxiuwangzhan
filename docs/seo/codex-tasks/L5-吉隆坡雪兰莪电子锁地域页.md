## 1. 项目背景

主站 `flashcast.com.my` 已有成熟的「服务 × 区域」交叉页体系：`/{lang}/locations/{area}/{service}`，由 `functions/_middleware.ts` + `functions/seo-manifest.json` + `scripts/seo-static-pages.mjs` 三层共同决定状态码与是否进 sitemap。

现状：

| 组合 | 状态 |
|---|---|
| `kuala-lumpur/digital-lock` | ✅ 已上线，H1「吉隆坡电子锁安装」，27,956 字节，`Service` + `FAQPage` schema 齐全 |
| 其余 9 个目标区域 | ❌ 不存在 |

电子锁的目标客户集中在公寓密集区与有地住宅区，但站点在这 9 个区没有任何可匹配 `digital lock {area}` / `kunci digital {area}` 的落地页。这是当前最便宜的增量流量入口。

## 5. 硬性实现要求

### 5.1 复用现有机制，不许新造

先读现有 `kuala-lumpur/digital-lock` 的完整实现链：

1. `src/components/services/serviceAreaPageText.json` 里 `"/locations/kuala-lumpur/digital-lock"` 的字段结构
2. `scripts/seo-static-pages.mjs` 里对应 3 条 `staticDefs`（`path` / `title` / `description` / `keywords` / `entityName` / `bodyHtml`）
3. `src/lib/serviceAreaRoutes.ts` 的 slug 映射

**照抄结构，只换区域与内容。** 若发现某层有硬编码导致新组合无法准入，输出诊断，不要自己改准入规则。

### 5.2 每组 meta 值（内容侧已定，直接使用）

**正文与字段来源**：`docs/seo/anzhe-lock-area-copy.json`（已交付，9 区 × zh/en）。
每个区域对象含 `title` / `description` / `keywords` / `h1` / `entityName` / `body`。
`body` 已按 ≥1,200 字符可见文本编写，直接作为 `bodyHtml` 使用，**不要改写正文内容**，只做字段映射。

注意：`shah-alam` 与 `kajang` 两组文案已备好，但能否上线取决于 CMS `service_areas` 是否有对应区域记录。没有就 404，文案留在文件里备用。

以 `petaling-jaya` 为例，其余按同一模板替换区域名：

```json
{
  "path": "/zh/locations/petaling-jaya/digital-lock",
  "title": "八打灵再也电子锁安装｜门体兼容核对｜FLASH CAST",
  "description": "八打灵再也公寓与有地住宅电子锁安装。先核对门厚、锁体与门框宽度，再供应、安装、录入使用者并做交付测试。",
  "keywords": "八打灵再也电子锁安装, 智能门锁, PJ 门锁更换",
  "entityName": "八打灵再也电子锁安装",
  "service": "digital-lock"
}
```

```json
{
  "path": "/en/locations/petaling-jaya/digital-lock",
  "title": "Digital Lock Installation Petaling Jaya｜Door Compatibility Check｜FLASH CAST",
  "description": "Digital lock supply and installation for Petaling Jaya condos and landed homes. Door thickness, lock body and frame width verified before installation, with handover testing.",
  "keywords": "digital lock installation petaling jaya, smart door lock PJ, condo door lock",
  "entityName": "Digital Lock Installation Petaling Jaya",
  "service": "digital-lock"
}
```

三语 `bodyHtml` 必须写出**该区独有**的内容，至少覆盖：

- 该区主流门型（如 Mont Kiara 多为防火木门 + 铁闸、Petaling Jaya 有地住宅多木门 + 铁花门）
- 铁闸与大门间距对安装方式的影响
- 公寓管理层/保安对施工时段与登门的限制
- 旧楼锁体实际差异（rim lock vs mortise）
- 服务响应与上门窗口

**禁止**：把 KL 那页正文复制过来只改地名。每页至少 1,200 字符可见文本，且与其他区页面的文本相似度必须明显不同（Codex 需输出每页前 200 字，供人工比对）。

### 5.3 ms 版本

本次**不做** ms 交叉页。若某层自动生成了 `/ms/...` 路径，必须保持 `noindex`，不得进 sitemap（现有 `hasCompleteMalayContent` 机制已保证）。

### 5.4 非法组合必须 404

`/zh/locations/puchong/bathroom-renovation` 这类未声明的组合必须 404，不许 fallback 到区域页或服务页。

## 9. 边界与失败处理

| 情况 | 处理 |
|---|---|
| CMS 无 `shah-alam` / `kajang` 区域记录 | 该组合 404，报告里说明，不许本地造 |
| 改动后现有 12 个组合任一变成 404 | 立即回滚，这是准入规则被破坏的信号 |
| `staticDefs` 加条目导致 `source_complete: false` | 补齐来源字段，不许把不可信标记塞进 sitemap |
| 正文写不出该区独有内容 | 宁可不做这一区，也不要复制 KL 正文 |
| 价格/工期/保修数字 | 一律不许编，写“以报价单载明为准” |
